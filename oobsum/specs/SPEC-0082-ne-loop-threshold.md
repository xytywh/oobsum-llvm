# SPEC-0082 循环头 widening 的符号阈值：`x != c` 结束的循环（`for (i = 0; i != n; i++)`、`for (q = p; q != p + n; q++)`）

状态：已实现
来源：循环探针（SPEC-0081 之后）：

```c
static void I1(UINT8 *p, UINT32 n) { UINT32 i; for (i = 0; i != n; i++) { p[i] = 0; } }      /* 原来 SUSPECT type_range_only */
static void P2(UINT8 *p, UINT32 n) { UINT8 *q; for (q = p; q != p + n; q++) { *q = 0; } }     /* 原来 SUSPECT pointer_stepping */
```

循环头 widening 把 `i` 的上界去掉（`[0, +inf]`），条件边 `i != n` 只在区间端点正好是 `n` 时收窄（`[lo, n] ∧ i ≠ n → [lo, n − 1]`），
上界已经没了，就收不回来。`<` 结束的循环靠条件边收窄，不受影响。

## 2. 设计

* 候选：循环头 H 出边上的比较 `x != c` / `x == c`（可隔着 `!`；`x` 隔着类型转换也行，只要转换前后的值相同），`x` 是本循环里被赋值的局部
  （整数或指针），H 本块的指令既不赋 `x`、也不赋 `c` 里用到的局部。
* 上升阶段，H 的入口状态 = widen(旧值, 旧值 ⊔ 这条入边的贡献)。widen 去掉了 `x` 的上界时：旧值与这条入边的贡献里
  `c` 是同一个确切值，`x` 的上界在**各自的**状态（类型范围 + 守卫）下都能证明 `≤ c` → 上界取 `c`（指针：同一基址，比偏移）。
  下界对称（`≥ c`，递减循环）。
* 可靠性：阈值只是候选的不变式。之后的迭代照常检查——这一圈回来的上界证明不了 `≤ c`（如 `i += 2`、`q` 按 4 字节走），
  widen 照旧去掉上界，回到原来的做法。上升结束时的状态仍是不动点，可靠。

结果：`i` 在头上是 `[0, n]`，循环体里 `i != n` 收成 `[0, n − 1]`（标签 `loop`），退出边 `i == n`。

* 指针循环第一圈 `q == p` 与 `p + n` 两边都是确切值、差不是常数：SPEC-0081 原来不产生信息，回边上就证明不了 `1 ≤ n`。
  改成按偏移走整数的同一套原子逻辑（偏移是数学整数，不用查忠实）：`p != p + n` → 守卫 `n >= 1`，差是常数仍直接判真假（修订 SPEC-0081 §2）。
* `!=` 在端点上收窄不推守卫原子（`<` 会推 `lo < x`）：少一个守卫只是更保守。

## 3. 对召回与误报的影响

**召回**：`!=` 结束、步长 1 的循环判出级别（原来记账）。**误报**：界内的判 SAFE（原来记账）。
步长不是 1 的（`i += 2`、结构体数组指针 `pst != ast + N`）照旧记账（以后：同余信息）。

# SPEC-0026 局部 / 全局结构体的字段值带进调用点（实参的 `fields`）

状态：已实现（S8c-2 的一项）
来源：`STATUS.md` S7d-4；06- D-25（指针实参 `{obj, have, alias?, eff_depth?, fields?}`）、A-12（内存格）、A-61（代换：`p0->f`、`ext(p0->f)` 由实参的 `fields` 给出）；
金标准 `LV5-01`（`Rrc_EncodeMsg_TP` 填好 `stCtx.pucBuf = aucBuf; stCtx.ulBufLen = 256;` 再传 `&stCtx`）。

## 1. 要解决什么

"链顶函数填好上下文结构体、一路传下去、底层按结构体里的长度写结构体里的指针"是报文编码的标准写法（05- 的"帧内字段存储"）。被调者的 Req 是
`p0->ulBufLen <= ext(p0->pucBuf)`；调用点记录没有字段的值，代换不下去，到入口只能记账。

## 2. 设计

调用点记录指针实参时：基址是**局部或全局的结构体变量**、偏移为 0，就看这个结构体的每个标量 / 指针字段在内存格里有没有值（A-12：本函数里存进去、
之后没有被调用或经未知指针的写清掉）：

* 指针字段：值的基址已知、大小已知 → `{obj, have}`（同普通指针实参，SPEC-0015 §2.1）；
* 整数字段：确切值 → 表达式；
* 没有值的字段不写（被调者的 `p0->f` 代换不了，照旧上传 / 记账）。

写成 `fields: {字段名: 值}`。数组字段不写（被调者以成员为界、`p0->aucBuf` 的大小来自类型）。

**别名实参的字段在本函数里改过**（A-61 的修正）：把自己的形参 `pK` 原样传下去（`alias pK`）时，被调者 Req 里的 `pK->f` 被代换成本函数**入口时**的
`pK->f`。若本函数在调用前写过这个字段（LV5-04：`pstCtx->ulBufLen += 16` 再调用），代换出来的是旧值——链顶再代入字段值，就会把越界证明成安全。
所以本函数记下写过的字段（按 `(基址, 偏移, 大小)`；偏移不定的写记"整个基址写过"；经未知指针的写、以及把这个指针（或任何未知指针）交给被调者的调用，
记"整个基址可能被改"）。别名实参上，**改过的字段**：内存格里有确切值就写进 `fields`（`ulBufLen: "p0->ulBufLen + 16"`），否则写成未知（`_unknown_<字段>`，
代换后只会走向 `entry_unproven`）；没改过的字段不写（照旧按别名代换成入口值）。

**内存格的失效（修订 A-12 的实现）**：常数偏移的写只失效同一基址上与 `[off, off + size)` 重叠的格，偏移不定时才失效整个基址。
原来每次写都清掉整个基址，连续给三个字段赋值只留下最后一个。

## 3. 对召回与误报的影响

只写本函数里确实存进去、且在调用前没有被清掉的值。被调者按字段值判定，原来到入口记账的变成有判定。

## 4. 实现位置

`core/Interp.cpp`：`RecordCall`（`ArgFields`）、`Step` 的 `Store`（按重叠失效内存格）。

## 5. 测试

* 单元测试 `InterpTest.ArgFields`：存两个字段后调用 → `fields` 两项；调用后再调用（格已清）→ 没有 `fields`。
* 单元测试 `InterpTest.AliasFieldWritten`：`p->len += 16` 再传 `p` → `fields: {len: "p0->len + 16"}`；写了不确切的值 → 未知；把 `p` 交给一个被调者之后再传 → 所有字段未知。
* `run.py csa`：LV5-04 TP 不能变成 SAFE（本 SPEC 修正前会：链顶代入字段值后把 `128 ≤ 128` 判安全）。
* lit `arg-fields.c`；`engine_check.py` LV5-01 视结果加入；`run.py csa` 无回退。

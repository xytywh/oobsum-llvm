# SPEC-0014 函数内解释第一步：无环代码的值与访问检查（`core/Interp`），产出 depth 0 的 Req

状态：已实现（S7a-1）
来源：`STATUS.md` S7（WP3）；06- §6.2（A-10…A-12 抽象域的子集）、§6.3（A-20…A-29 转移）、§6.4（A-40…A-45 访问检查与 Req 生成）、
D-20（接口符号与对象写法）、D-23（Req 字段）；金标准 `cases/summaries/` 里各函数 depth 0 的 Req（如 `Stat_Inc`：
`W4 @ g:g_aulCellStat`、`end [4*p0 + 4, 4*p0 + 4]`、`absorbed` 里一条同末端的 R）。

## 1. 要解决什么

S8a / S8b 已经证明：给定每个函数的局部事实（depth 0 的 Req、调用点记录），C++ 能推出与金标准相同的告警。S7 要从 FIR **算出**这些局部事实。
本步先做最基础的一层：在没有循环、不看条件边的情况下，把 FIR 的值算成接口符号的线性式，在每条 `load` / `store` 上做访问检查，
生成 depth 0 的 Req。条件边与守卫（S7b）、循环（S7c）、调用点记录与效果（S7a-2、S7d）在后面几步。

## 2. 设计

### 2.1 值（A-10、A-11 的子集）

* 整数值 `IntVal`：**确切值**（一个 `LinExpr`，只含接口符号）或**区间** `[lo, hi]`（`lo` / `hi` 各为 `LinExpr` 或无界）带来源标签；
  未知时带原因。
* 指针值 `PtrVal`：基址 + 字节偏移（`IntVal`）。基址：形参 `Param(i)`（对象 `*pi`，大小 `ext(pi)`）、全局 `Global(键)`（对象 `g:名`，大小取 FIR
  里全局的类型大小，不完整的为未知）、局部对象 `Local(id)`（对象 `local:名`，大小为类型大小）、字符串字面量（大小 `长度 + 1`）、
  形参所指结构体里的数组成员（`fld` 收窄，对象 `pi->名`，大小为成员大小，D-20）、未知。
* 入口状态：整数形参 = `pi`（确切）；指针形参 = `Param(i) + 0`；其余局部未知（`uninit`）。

### 2.2 转移（A-20…A-29 的子集）

| FIR | 规则 |
|---|---|
| `c`、`l` | 常数；局部的当前值 |
| 数学整数的 `+ - *` | 确切值逐项算；乘常数、乘确切的常数；两个非常数相乘 → 不透明 `mul(a, b)`（A-22）；区间逐端点算 |
| `/ c`、`>> k` | 确切值 → 不透明 `div(e, c)` / `div(e, 2^k)`（A-23，不丢成 ∞） |
| `% c`、`& (2^k − 1)` | 确切值 → 不透明 `mod(e, c)`（A-24 的界 `[0, c − 1]` 由 `SymEnv` 给出，标签 `mask`）；`& m`（其它常数）→ 区间 `[0, m]`（`mask`） |
| `<< k` | 乘 `2^k` |
| 回绕形（C 的整数运算）`(a op b):uW` | 先按数学整数算；**无符号减法**的结果不能证明非负时 → `wrapW(·)`（A-26；W 为 16 / 32 时用不透明项，其它宽度为类型范围、标签 `type`）；常数直接按 `2^W` 取模；无符号加法、乘法与有符号运算不加回绕（溢出按 06- A-21 不考虑：有符号是未定义行为，无符号加法溢出在本规则的场景里视作无关） |
| `cast` | 常数截断 / 符号扩展；确切的符号值：目标宽度不小于源宽度且符号兼容时不变，否则为目标类型范围（`type`，A-27） |
| 比较、`!` | `[0, 1]` |
| `laddr` / `gaddr` / `str` / `faddr`、`padd`、`fld`、`psub` | 见 §2.1；`padd` 把偏移相加；`psub` 同基址时为偏移差除以元素大小 |
| `unk` / `havoc` | 未知，带原因 |

**内存格**（A-12）：以（基址, 常数偏移, 字节数）为键；`store` 到常数偏移 → 强更新；到非常数偏移 → 失效该基址上的格；经未知基址的写 → 失效全部格。
`load`：命中格 → 格的值；形参所指结构体里常数偏移处的字段（按 FIR 的记录布局）→ 符号 `pi->字段`（首次读到即入口值，D-20）；
全局标量 → `g:名`（A-28）；其余 → 未知（`data`）。

### 2.3 控制流（本步）

块按逆后序处理；汇合点逐局部合并（A-15 的子集）：相等则保持；两个确切值差为常数 → 区间（大者为上界）；其余未知（`imprecise_join`）。
条件边的 `assume` 本步不用（过近似，对召回安全，S7b 加）。**有回边的函数本步不分析**：状态 `partial:loop_pending`，不产出 Req（S7c 补上之前，
引擎接上时这些函数按"没分析完"报 `SUSPECT:unanalyzed:…`，SPEC-0001 §2）。

### 2.4 访问检查与 Req（A-40…A-45 的子集）

每条 `load`（R）/ `store`（W）：

* 基址未知 → 账本 `untracked_pointer`；对象大小未知（不完整的 `extern` 数组等）→ `alloc_size_unknown`（A-45）。
* `have` = 基址的大小（形参为 `ext(pi)`）；`end` = 偏移 + 字节数：偏移确切 → `[e, e]`、标签 `exact`；偏移是区间 → `[lo + n, hi + n]`、标签取区间的；
  上界无界 → 账本 `type_range_only`。
* 其它字段：`obj`、`kind`、`start`（偏移的下界）、`guard`（本步为空）、`access`（`fn`、`key`、`at` = `文件名:行`、`end` = 上界）、`path` = `[函数@文件名:行]`、
  `depth = 0`、`eff_depth = 0`、`blind`（A-07 的 `sub` 且基址来自数组中段——本步恒为 false）。
* **覆盖合并**（A-44）：同一 `have`、对象、守卫，`end` 上界恒不大于另一条（差为非正常数）的那条并进去，记进 `absorbed`；差为 0 时**写优先**
  （`g[i]++` 的读写合成一条 W、R 进 `absorbed`，与金标准相同），再按出现顺序。

## 3. 对召回与误报的影响

不接进 checker。设计上的召回考虑：不能证明非负的无符号减法一律回绕（宁可多报）；条件边本步不用（多报 SUSPECT，不会少报）；
有回边的函数本步不产出 Req，但会标出来，引擎接上前必须由 S7c 补齐。

## 5. 测试

单元测试 `InterpTest.cpp`（手工构造 FIR）：`g[i]++`（W + absorbed R，`end 4*p0 + 4`、`have 16`、`g:` 对象）、`p[16] = 0`（`*p0`、`ext(p0)`、`end 17`）、
`p[n - 1]`（`wrap32(p1 - 1) + 1`）、局部数组常数下标（`local:` 对象、常数 `have`）、形参结构体字段的读（`p0->ulLen` 进下标）、数组成员 `fld` 收窄
（`p0->aucBuf`）、`% 8` 与 `& 7` 与 `& 6`、`/ 4` 与 `>> 2`、两个变量相乘、`cast` 截断、汇合（常数差的区间、不可比的未知）、未知基址进账本、
有回边 → `partial:loop_pending`。

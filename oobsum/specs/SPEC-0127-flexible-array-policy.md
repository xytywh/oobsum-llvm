# SPEC-0127 尾部小数组的可配置报告策略

状态：已实现
来源：用户实际告警中的结构体尾数组；明确要求最后一个静态数组成员、元素数 <=4 视作可变数组约定，默认不告警，可配置阈值与打开报告。

## 1. 要解决什么
不能把尾部 [0] / [1] / [4] 的声明长度直接当成业务分配的 payload 长度，并因此产生难以使用的告警。

## 2. 设计
FlexibleArrayMax=4，ReportFlexibleArray=false。真正的 [] 始终是候选；结构体（不含 union）的最后一个定长数组，元素数 <= 阈值是候选。
阈值 0 只保留 [] / [0]。独立数组、非最后的成员、union 和超过阈值的尾数组照常检查。
FIR 的 tail(pointer,declared_count) 只加来源标签；PtrVal、实参 / 字段、返回指针效果、Req 和调用点判定传播标签，不改大小和越界证明。
候选的原标签照常计算并写日志，默认由 Policy 标 not_emitted_because=flexible_array；绝不能写成 SAFE。打开 ReportFlexibleArray 后按原标签报告。
汇合仅在所有可能指针都是候选时保留（取声明元素数最大值）；有普通指针的路径时仍报告。
不同尾数组标签的 Req 不能互相覆盖，否则会把普通访问藏在被抑制的候选里。断链 / 未分析函数的独立账本仍保留。

## 3. 对召回与误报的影响
这是用户明确选择的报告策略例外：可能同时不报真越界；原始判断全部留日志，选项 true 恢复报告能力，不改推理标签。
回归量尺明确单列策略过滤，基线比较仅允许同一次访问、仍有原标签的 flexible_array 过滤；不能用它豁免其它消失的报告。

## 4. 实现位置
FIR / lower、PtrVal / effects、Summary / Apply / Solver / replay、Policy、checker 选项、量尺与测试。

## 5. 测试
[] / [0] / [1] / [4] 正向跨层；阈值0；报告开关；非末尾 / [5] / 独立数组 / union 保留报告；普通指针和尾数组汇合不能静默；返回指针与字段中转。
core 170/170、lit 114/114、replay 一致、engine_check 维持 14/16；Dump=fir+summary+state+decisions 可落盘。
默认 csa 通过108、通过+S20、级别不同2、超出预期3、策略过滤1，TN零强告警、回退0；打开 ReportFlexibleArray 后恢复原108/20/2/4、回退0。
策略过滤的是 LV7-01 的超出预期 TP；LV4-02 因不合并不同策略标签的 Req，多保留一条 DEFINITE，不改级别。
固定内层数组、普通指针汇合、返回新对象的混合来源均有回归，保证不随候选被过滤。

## 6. 调试
FIR tail 节点；state 的 tail=count；摘要 / 判定 flex 字段；日志中的 flexible_array 与原 label。

## 7. 对主规格的修订
D-37 增加用户约定的可配置尾数组策略；I-31/I-32 新增两选项；T-03 增加明确策略过滤口径；D16 的安全证明不变，报告例外可审计。

## 8. 公司侧验证
COMPANY.md 下一清单：默认与 ReportFlexibleArray=true 的判定标签应一致，只差过滤与合并后的告警；在公司核查候选是否符合真实分配约定。

## 9. 待定 / 以后
不推断 runtime payload 长度，也不假定不跟踪的字段链是尾数组；无法传播来源时保守报告。

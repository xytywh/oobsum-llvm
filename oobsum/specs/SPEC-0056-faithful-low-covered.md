# SPEC-0056 无符号区间下界盖住 0 时可信：`i <= n` 的循环不再多估 2（误报）

状态：已实现
来源：STATUS 已知问题"`i <= n` 的循环把 `i` 的上界多估了 2"；探针 `for (i = 0; i <= n; i++) p[i] = 0;` 以 `n = 15`、16 字节数组调用（安全）被报成
POSSIBLE（"up to byte 18"）——**误报**。`i <= 15`（常数）、`i < n`（符号）都正常。06- A-16、SPEC-0016（忠实的比较）、SPEC-0023 §2。

## 1. 原因（`Dump=state`）

收窄阶段循环头 `[0, p1 + 1]`；上界 `p1 + 1` 可能超过 u32 最大值，`FaithfulAs` 认为这个区间不可信 → 条件 `i <= p1` 不收窄 → 循环体 `[0, p1 + 1]` →
回边 `[0, p1 + 2]`，第二遍收窄后循环头、循环体都是 `[0, p1 + 2]`。

## 2. 设计

`FaithfulAs`（区间）：**无符号**类型、下界不大于类型最小值（`coversLo`）时就算可信，不再要求上界落在类型范围内。

可靠：设数学值落在 `[lo, hi]`、`lo <= 0`。真实值 = 数学值 mod 2^w：没回绕时就是数学值；回绕时在 `[0, 数学值 − k·2^w]` 里，`>= 0 >= lo`、`<= 数学值 <= hi`。
所以区间包住所有真实值。在它上面按条件收窄（条件成立的真实值满足条件）得到的区间也包住条件成立的真实值。下界大于 0 时（`[1, +inf]`、`[5, p1 + 1]`）照旧要求上界在类型范围内
（回绕后的真实值可能小于下界，SPEC-0050 的情形）。

## 3. 对召回与误报的影响

**误报减少**：`i <= n` 的循环判对上界（`n = 15` 的 16 字节 → SAFE，`n = 16` → POSSIBLE，末端 17）。召回：收窄可靠（§2），不会把真越界判成 SAFE；回归用例守住。

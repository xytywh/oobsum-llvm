# SPEC-0076 有符号区间的符号界按"溢出是未定义行为"认作可信：`for (i = n − 1; i >= 0; i--)` 收得住

状态：已实现
来源：递减循环探针：

```c
static void D3(UINT8 *p, INT32 n) { INT32 i; for (i = n - 1; i >= 0; i--) { p[i] = 0; } }
void D3_TP(void) { UINT8 a[16]; D3(a, 17); }   /* 原来：被调者里 type_range_only */
void D3_TN(void) { UINT8 a[16]; D3(a, 16); }
```

循环头 `i ∈ [-inf, p1 − 1]`，条件 `i >= 0` 该把下界收成 0，但 `FaithfulAs` 认为上界 `p1 − 1` 在 `p1 = INT_MIN` 时会溢出 → 区间不可信 → 不收窄。
06- A-21 / SPEC-0014 §2.3 已定：**有符号运算的溢出是未定义行为，不考虑**（有符号运算不加回绕）；SPEC-0050 也据此把"缺界的有符号区间"认作可信。
"界是有符号算术、范围超出类型"这一情形没跟上这条政策。

## 2. 设计

`FaithfulAs`（区间）：类型是有符号时，**不是常数**的界直接算可信（常数界照旧查是否在类型范围内）；盖住类型最小 / 最大值的界也算可信
（汇合时 `min(p1 − 1, −1)` 会按类型范围放宽成比 `INT_MIN` 还小的常数，比如 `-2147483649`——它只是比类型最小值更松的下界）。

为什么只有有符号算术会让符号界超出类型：不保值的转换（`(INT32)u32`、`(INT16)i32`…）在 `Cast` 里一律落到类型范围（A-27），
保值的转换（`(INT32)u16`）范围本来就在里面——有符号值里的符号式超出类型，只能来自有符号的加减乘溢出，按 A-21 不考虑。

## 3. 对召回与误报的影响

**召回**：有符号递减循环（`for (i = n − 1; i >= 0; i--)`）判出级别（原来记账）。**误报**：界内的判 SAFE。
取舍同 A-21：真靠有符号溢出越界的代码（未定义行为）不在本规则范围。

# SPEC-0045 mod-ref：摘要记"可能写哪些位置"，调用点只让这些位置失效

状态：已实现
来源：`STATUS.md` S8c-2（mod-ref）；SPEC-0040 / SPEC-0041 §3（为了不错判 SAFE 采取的保守做法：指针交给过被调者的对象整块、调用过任何函数后的全部全局，
都不再用入口值）。探针：`Msg_SetType(p)` 只写 `p->ulType`、`Cnt_Inc()` 只写 `g_ulCnt`、`Msg_Zero(p)` 经两层只写 `p->aucData`，之后读 `p->ulLen` /
`g_ulLen` 都成了"只剩类型范围"（SUSPECT），应为 DEFINITE / POSSIBLE。06- D-24（效果）、A-12、A-28。

## 1. 要解决什么

业务代码里"先 `Msg_Init(p)` / `Stat_Inc()` 再按 `p->ulLen` / 全局配置拷贝"非常常见；被调者大多只写一两个字段，保守失效会把这些长度全变成 SUSPECT。

## 2. 设计

### 2.1 摘要字段 `mods`（排序、去重的字符串）

| 写法 | 含义 |
|---|---|
| `pK` | 第 K 个形参所指对象，整块可能被写（偏移不定、交给了不知道写哪里的被调者） |
| `pK+off:size` | `*pK` 的 `[off, off + size)` 字节可能被写 |
| `*pK->f` | `*pK` 的指针字段 `f` 所指的内存可能被写 |
| `g:名字` | 这个全局可能被写 |
| `g:*` | 某个全局可能被写（调用了不在模型表、又没有摘要的函数） |
| `*` | 任何内存都可能被写（经未知指针写、把未知指针交给了被调者） |

### 2.2 本函数产生的（记录那一遍）

* store：未知基址 → `*`；形参基址常数偏移 → `pK+off:size`，否则 `pK`；形参所指结构体的成员数组 → `pK+成员偏移(+下标):size`，下标不定时整个成员；
  形参指针字段所指 → `*pK->f`；全局 → `g:名字`；局部、堆、字符串 → 不记（调用方看不到）。
* 访问类模型的目的一侧：同 store（整块 / 成员）。
* 调用：见 §2.3。

### 2.3 调用点（被调者有摘要：本 TU / solve 时已算出、不在模型表里的直接调用）

被调者的每条 `mods` 换成调用方的说法并照做（只让这些位置失效），同时并进调用方自己的 `mods`：

* `*` → `clobbered`、`called`、清所有格；`g:*` → `called`、清全局的格；`g:名字` → 这个全局记进 `writtenAll`、清它的格；
* `pK…` → 第 K 个实参：未知指针 → 当 `*`；基址 B、偏移常数 `o`：`pK+off:size` → `written` 记 `(B, o + off, size)`、清重叠的格；`pK` 或偏移不定 → B 整块
  （`MarkWritten`，含 SPEC-0040 的同类型形参别名）；
* `*pK->f` → 第 K 个实参是调用方形参 `pJ`（偏移 0）时记 `*pJ->f`；否则不处理（指针字段所指的是数据缓冲区，按 SPEC-0040 的取舍不当成会改结构体 / 标量）。

被调者没有摘要（跨 TU 的 `not_in_tu`、函数指针、递归环里还没算出的）：照旧保守（清所有格、指针实参整块、`called`），并给调用方的 `mods` 记
每个指针实参的整块（换算同上）与 `g:*`——保证往上传递时仍是可靠的上界。

### 2.4 纯函数、释放函数、分配器

不变（不写被跟踪的内存）。

## 3. 对召回与误报的影响

**误报减少**：被调者没写到的字段 / 全局在调用后仍用入口值。**召回**：`mods` 是可能写的位置的上界（本函数的写 + 被调者换算过来的 + 没摘要时的保守整块），
没写到的位置在调用前后一样，所以收紧是可靠的；回归用例守住"被调者写了 ulLen / g_ulLen"仍不是 SAFE（SPEC-0040 / 0041 的用例不变）。

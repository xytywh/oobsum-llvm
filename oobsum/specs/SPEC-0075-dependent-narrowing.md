# SPEC-0075 条件边收窄后重算同一块里依赖它的局部：`while (n--)` 不再丢界

状态：已实现
来源：递减循环探针：

```c
static void D2(UINT8 *p, UINT32 n) { while (n--) { p[n] = 0; } }
void D2_TP(void) { UINT8 a[16]; D2(a, 17); }   /* 原来：SUSPECT type_range_only（"up to byte 4294967296"） */
void D2_TN(void) { UINT8 a[16]; D2(a, 16); }   /* 原来：同上 */
```

`while (n--)` / `if (len-- > 0)` 在 C 里极常见。降级后是 `t = n; n = (t − 1):u32; 分支 t != 0`：条件收窄的是临时局部 `t`，
而 `n` 已经按收窄前的 `t` 算好（`t` 可能是 0，`n` 回绕成类型最大值）——`n = t − 1` 这层关系在边上丢了。06- A-13（定义式）、SPEC-0016（条件收窄）。

## 2. 设计

`FlowOut`：走完块里的指令后，找出**可重算的定义**——`Y = E`（`set`），`Y` 在块里之后没再被赋值，`E` 里出现的局部 `X` 都不是 `Y` 自己、在这条 `set` 之后也没再被赋值
（`E` 是纯表达式，没有内存读）。于是在块的出口处 `Y` 的值就是 `E` 在出口处各局部当前值下的值。

条件边上 `Assume` 收窄之后：某个可重算定义 `Y = E` 里的局部被收窄了（值变了），**或者这条边新加了守卫**（确切值收窄不了，只加守卫，
如第一轮的 `t = p1` 在 `t != 0` 边上得到 `p1 >= 1`，这时 `(p1 − 1):u32` 才能证明不回绕），而 `Y` 本身没被这次收窄改过 → `Y` 按收窄后的值重算（`Eval(E)`）。
可靠：边上各局部的真实值满足条件，`Y` 的真实值就是 `E` 在这些值下的值，重算是它的过近似。只重算一层。

## 3. 对召回与误报的影响

**召回**：`while (n--)` 的越界判出级别（原来记账）。**误报**：界内的判 SAFE（原来记账）。

# SPEC-0025 校验函数的条件效应（`ret_cond`）：返回值是哪个常数时，形参满足什么

状态：已实现（S8c-2 的一项）
来源：`STATUS.md` S8c-2；06- D-24（效果 `ret_cond`：`{when: "ret == c", then: [条件…]}`）、A-63…A-65（效果的代入）、A-14（守卫）；
金标准 `LV4-06`（`Cell_IsValidId` → `Cell_CheckPara` → `if (Cell_CheckPara(id) != VOS_OK) return;`）。

## 1. 要解决什么

业务代码几乎都把校验放在单独的函数里：`if (Cell_CheckPara(id) != VOS_OK) return; Ctx_Clear(id);`。真正的比较在两层之下，调用方的守卫丢了，
`Ctx_Clear` 的 `id ≤ 15` 到入口只能记账（LV4-06 TP 期望 L2：校验函数自己差了一，`id ≤ 16`）。

## 2. 设计

### 2.1 值的"情形"

整数值可以带若干**情形**（至多 4 个）：`{常数 c, 取 c 时成立的守卫}`。它只在两处产生：

* **汇合**：两边是不同的常数（或已带情形）→ 合成区间，并带上两边各自的情形（同一个常数出现在两边时守卫取交集）。`?:`、`if … x = 1; else x = 0;` 都走这里。
* **调用点代入**被调者的 `ret_cond`（§2.3）。

复制（局部赋值）保留情形；参与运算、与非常数汇合、循环头 widening 时丢掉。

### 2.2 效果的产生（被调者）

记录那一遍收集每个 `ret` 的（值、当时的守卫）。每个返回值都是常数（或带情形的值，每个情形连同当时的守卫算一次）时，
按常数分组，组内守卫取交集：`{kind: ret_cond, when: "ret == c", then: [守卫…]}`（守卫为空的不写）。有一个返回值不是常数也不带情形 → 没有 `ret_cond`
（那条路径可能返回任何值，"返回 c ⇒ 守卫"就不成立）。

### 2.3 效果的代入（调用方）

调用本 TU 里已算出摘要、带 `ret_cond` 的被调者：返回值是这些常数组成的区间（标签 `const`），并带情形——守卫里被调者的形参换成实参的值
（实参都是忠实的确切值才换；换不了的那条情形不带守卫）。

### 2.4 条件边

`a op k`（`a` 带情形、`k` 是常数）：留下满足 `c op k` 的情形；一个都不剩 → 这条边不可达；否则把留下的情形的守卫交集加进状态。
`if (Cell_CheckPara(id) != VOS_OK) return;` 的假边（`== 0`）→ 加 `p0 <= 16`。

## 3. 对召回与误报的影响

只用到"每条返回路径都是常数"时才成立的条件；守卫是代码里真实的检查。收益是精度（LV4-06 TP：`ulCellId ∈ [0, 16]` → 调用点 F-12b → L2；TN `[0, 15]` → 安全），
原来记账的入口变成有判定。

## 4. 实现位置

`core/Interp.{h,cpp}`：`IntVal` 的 `cases`、`Join` 产生情形、`RecordReturn` 记守卫、`Effects` 的 `ret_cond`、调用点代入、`AssumeCmp` 按情形筛选。

## 5. 测试

* 单元测试 `InterpTest.RetCondEffect`：`?:` 的校验函数 → `ret_cond` 两条；不全是常数时没有；调用方 `!= 0` 的边加守卫、`== 2` 不可达。
* 单元测试 `EngineTest` / lit `ret-cond.c`：两层校验 + 差一 → POSSIBLE；正确的校验 → SAFE。
* `engine_check.py`：LV4-06 视结果加入；`run.py csa` 无回退。

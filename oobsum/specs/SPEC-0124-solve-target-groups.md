# SPEC-0124 全局求解按目标隔离

状态：已实现
来源：用户全板的目标统计：10235 个 aarch64_be ILP32 TU 与 10 个 x86_64 LP64 TU 在同一 WorkDir。当前只按函数键去重，会混用不同 ABI 的大小 / 摘要。

## 1. 要解决什么
一个架构的同名函数不应覆盖另一个架构的定义；全局大小表也不能跨目标共享。

## 2. 设计
checker 读 FIR 后，按 (triple, ptr, long, big_endian) 分组，每组独立调用原 RunSolve，按原 TU id 写回 solved；组间不代换。
摘要文件 stem 包含目标，索引注明目标；进度在多组时标出组号，单组协议保持不变。最后 done 表示所有组写完。
直接调用 core RunSolve 的使用者应给同一目标的模块。
同一源文件有不同编译配置时，现有 TuId 仅基于主文件路径，不能保存多个变体；本步不假装解决这个独立边界。公司需先确认重复条目是否只是相同编译命令。

## 3. 对召回与误报的影响
修正混目标下的错误 SAFE / 错误越界 / 某些 TU 的函数被丢弃。单目标结果逐字不变；跨目标找不到定义时照常 SUSPECT unknown_callee。

## 4. 实现位置
checker::solveAll 分组；摘要索引；文档与 lit。

## 5. 测试
两个目标含相同外部函数名：一个 4 字节对象越界，另一个 16 字节对象安全，两份 TU 均有正确结果，重复 solve 幂等。lit 111/111、core 161、replay 一致、csa 回退 0 / TN 零强告警、engine_check 维持 14/16；重复求解字节一致。

## 6. 调试
Dump=progress+summary+stats，进度组号与摘要索引 target。

## 7. 对主规格的修订
X-03、N-07：同一求解域内目标一致，混合 WorkDir 分组。

## 8. 公司侧验证
COMPANY.md 新清单，全板日志应出现两个目标组。只带回组数、各目标 TU 数和标签计数，不带业务名字。

## 9. 待定 / 以后
同一主文件的多编译变体需要单独设计，不在本步改 TuId / 指纹规则。

# SPEC-0057 间接调用把指针交出去时，调用点记账 `fptr`

状态：已实现
来源：查 LV9-01（函数指针）时发现：`RecordCall` 对间接调用直接返回（注释"间接调用（fptr）留到 S9"，之后一直没做）——摘要的 `calls` 里没有它，账本里也没有
`fptr`。06- A-60 ①：间接调用解析不出目标时**记账 `fptr`**；D-27 的账本原因里有 `fptr`。

后果：经函数指针把缓冲区交出去的路径**悄悄断掉**。LV9-01 里目标函数恰好没有别的调用方、被当成入口，访问才照样报了出来；目标函数另有静态调用方时，
它的 Req 只上传给静态调用方，经函数指针的那条调用链就没人查（不报、也不记账）。

## 2. 设计

间接调用（`calleeExpr` 不为空、没被解析成直接调用——S9.1 以后再做）：实参里有指针（不是函数地址）时，在调用点记账 `fptr`（本函数的账本，SUSPECT），
文本"a pointer is passed through a function pointer whose target is not resolved"。只有整数实参的不记（不经被跟踪的对象）。调用后的失效照旧保守（清格、指针实参整块、`called`、
`mods` 记整块与 `g:*`，SPEC-0045）。

## 3. 对召回与误报的影响

**召回**：经函数指针交出去的指针至少有一条 SUSPECT（原来什么都没有）。噪声：业务里回调 / 函数表调用多的地方每个调用点一条 `fptr`（可以用 `SuspectReasons` 过滤），
S9.1 解析出目标后会少一部分。

## 4. 实现位置

`core/Interp.cpp`（`RecordCall`）、`core/Engine.cpp`（`LedgerMessage`）。

## 5. 测试

* lit `fptr-ledger.test`：局部函数指针、结构体里的函数指针字段各一次间接调用传指针 → `SUSPECT:fptr`；只传整数的间接调用 → 不记；直接调用照旧。
* `run.py csa`：回退 0（LV9-* 多出 `fptr` 记账，原来的判定不变）。

## 6. 调试

`Dump=summary`（`opens` 的 `fptr`）。

## 7. 对主规格的修订

无（按 06- A-60 ①、D-27 实现）。

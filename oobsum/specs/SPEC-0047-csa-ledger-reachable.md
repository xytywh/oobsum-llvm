# SPEC-0047 `run.py csa`：期望"记账"的入口，账本可以在它调用链上的函数里

状态：已实现
来源：`run.py csa` 的"漏报 13"里，12 个是期望"记账"的 TP 入口：判定日志里**有**报出的 SUSPECT，但记在被调者里（本函数账本，如 LV7-04 的
`Buf_CopyStep` 指针步进；或没有调用方、被当成入口的函数），量尺只看归在入口函数名下的判定，于是算成漏报。06- §1.2（`记账` 的应在账本里有对应原因）、
SPEC-0002 §2.2 / §2.3（入口的实际与对照口径）。只改测量，不改 checker。

## 2. 设计

* `run.py csa` 跑 cc1 时加 `Dump=summary`（`--config` 里已有 `Dump=` 时不加）：从 stderr 的 `[oobsum:summary]` 行取每个函数的键与 `calls[].callee_key`，建调用图。
  调试输出不影响结果（CLAUDE.md §5.5）。
* 期望 `记账` 的 **TP** 入口，归在入口名下的判定里没有报出的 SUSPECT / DEFINITE / POSSIBLE 时：看从入口经**静态调用**能到达的函数里报出的判定；有 SUSPECT
  就当作这个入口的实际（显示 `SUSPECT:<原因>@<函数名>`），对照为"通过"。
* 经函数指针调用的目标不在静态调用图里，照旧"漏报"（如实反映：S9.1 函数指针解析以后）。L1 / L2 期望的入口不变（要在入口的调用链上判出级别）。
* 回退检查不变（按报出的判定比，与入口口径无关）。

## 3. 对召回与误报的影响

无（测量）。"漏报"只剩真正一条都没有的入口。

## 4. 实现位置

`oobsum/cases/run.py`（`cmd_csa`：取摘要建调用图；入口的实际）。

## 5. 测试

* `run.py csa`：LV7-04、LV6-03…05、LV7-06、LV8-02…04、LV9-04、LV10-02 等期望"记账"的 TP 从"漏报"变成"通过"；基线有意更新。
* lit `cases-csa.test`（`Phase=report`，没有摘要）的结果不变。

## 6. 调试

`cmake-build-release/oobsum-csa/<用例>/stderr.txt`（摘要行）、`csa-result.json` 的 `actual`。

# SPEC-0110 两边都是区间的比较也收窄：`i < n`、`n ∈ [lo, hi]` → `i ≤ hi − 1`

状态：已实现
来源：S7c-2（带 min / max 的界）排查。嵌入式代码里很常见的"先把长度夹到上限再循环"：
```c
UINT32 n = ulLen > 16 ? 16 : ulLen;          /* n ∈ [0, 16]（两条路各自的守卫下，SPEC-0042） */
for (i = 0; i < n; i++) { pucDst[i] = pucSrc[i]; }
```
`AssumeCmp` 只在一边是确切值时收窄另一边（SPEC-0017 §2.3），`n` 是区间，`i` 不收窄——加宽到 `[0, +∞)`，被调者里记账 `type_range_only`，
TP（目的 8 字节）、TN（目的 16 字节）都报 SUSPECT。

## 2. 设计

* `AssumeCmp`：两边都是区间（且都忠实，原有的判断不变）时，用另一边的界收窄（`Narrow`，写回局部）：
  * `a < b` / `a <= b`：`a < b ≤ hi(b)` → 按 `hi(b)` 收窄 `a`；`b > a ≥ lo(a)` → 按 `lo(a)` 收窄 `b`。
  * `a > b` / `a >= b`：对称。`a == b`：两边互相按对方的上下界收窄。`!=`：不收窄。
  * 只用**代码给出的界**（`IsCodeTag`：确切、常数、检查、分支、循环、守卫、返回值、模型、掩码）。另一边的界只来自类型 / 数据 / 加宽时不用——
    收窄出来的界会标成 `loop` / `check`（代码给出的），拿类型范围当它会把只该记账的访问判成 POSSIBLE。
  * 收窄后为空 → 这条边走不到（同原来）。
* 不产生守卫原子（原子仍只在一边确切时产生）。

## 3. 对召回与误报的影响

只收紧区间：原来只能记账的访问可能证明安全（证明了才不报）或判出 POSSIBLE。召回不降：收窄依据的是 `a < b` 与 `b` 的上界都成立。

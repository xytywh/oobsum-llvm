# SPEC-0050 无符号局部 widening 后补上类型范围的界（从 1 开始的循环不再丢界）

状态：已实现
来源：做 SPEC-0049 时发现（改动之前的代码也一样）：`for (u = 1; u <= 16; u++)`、`for (u = 1; u < 17; u++)` 的循环头是 `?(imprecise_join)`（Top），
`for (u = 0; …)` 正常。业务里 `for (i = 1; i < n; i++)` 很常见，丢界就意味着这些访问全变成记账。06- A-16（widening）、SPEC-0016（忠实的比较）、SPEC-0023 §2。

## 1. 原因（`Dump=state` 与临时跟踪）

1. 第二轮汇合 `[1, 2]`，widen 成 `[1, +inf]`；
2. `u <=u 16` 收不住它：`FaithfulAs` 认为无符号的 `[1, +inf]` 不可信（上界超出 u32，可能已经回绕，回绕后可以小于下界 1）；`[0, +inf]` 正好盖住整个类型范围，所以从 0 开始的不受影响；
3. 循环体里 `u + 1` 的 u32 加法在输入没有上界时按可能回绕处理，下界回到 0 → 回边 `[0, +inf]`；下界变小，widening 把下界也去掉 → `[-inf, +inf]` → Top。

## 2. 设计

循环头 widening（`WidenState`）之后，对本循环里被赋值的（SPEC-0046）**无符号整数局部**（宽度 < 63）：区间缺上界补成 `2^w − 1`、缺下界补成 `0`，标签仍是 `widen`。

* 可靠：u32 的真实值本来就在 `[0, 2^w − 1]` 里，补上的界不会排除任何真实值；回绕后的值也在这个范围内。
* 补上之后值落在类型范围内，`FaithfulAs` 认为可信 → 循环条件能收住它 → 循环体 `[1, 16]`、回边 `[2, 17]`，不再掉下界；收窄后循环头 `[1, 17]`。
* 有符号局部不变（`FaithfulAs` 对有符号没有上界的已经认为可信：有符号溢出是未定义行为）。
* **收窄之后**仍停在类型最大值（及以上）、来源还是 `widen` 的上界：补上的界没被循环条件收住，恢复成"没有上界"——没收住的循环的记账方式
  （本函数账本 `type_range_only` / `pointer_stepping`）与原来一样；收住的循环保留循环条件给出的界。

## 3. 对召回与误报的影响

**召回 / 误报减少**：从非 0 开始的无符号循环的下标、长度判出 L1 / L2 / SAFE（原来记账）。真的停不下来的循环（没有条件收住）照旧是整个类型范围（`widen`，
不算代码给出的界 → 记账），与原来一样。

## 4. 实现位置

`core/Interp.cpp`：`Analyzer::Run` 的上升阶段（循环头 widening 之后补界）与收窄之后（去掉没收住的补界）。

## 5. 测试

* lit `widen-unsigned.test`：`for (u = 1; u <= 16; u++) p[u - 1]` → SAFE（16 字节）、`p[u]` → POSSIBLE（越界 1）；`for (u = 1; u < 17; u++)` 同；
  `Dump=state` 的循环头是 `[1, 17]`；对照：`for (u = 1; ; u++)`（没有条件）→ 循环头 `[0, +inf]:widen`，照旧在本函数记账 `type_range_only`。
* 单测、`nested-loop.test`（内层改外层变量 → `[0, +inf]:widen`）不变。
* `run.py csa` 无回退；`replay.py`、`engine_check` 不回退。

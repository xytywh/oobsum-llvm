# SPEC-0134 分阶段稳定性比较，默认仅输出计数

状态：已实现
来源：用户多轮最终报告有差异；仅比较报告总数不能区分export覆盖、求解差异、报告文本/顺序或收集元数据。

## 1. 设计
新增compare_runs.py，输入两个完整WorkDir，--through=export/solve/report选择已完成阶段；报告路径可显式给出，默认WorkDir/report.json。
FIR/solved/decisions按相对文件名和流式SHA256比较，给新增/减少/内容变化文件数，不用把大FIR解析一遍；*.tmp和冲突标记单独诊断。
报告只比较本规则problems的多重集合，忽略数组排列但保留重复次数；分别比较完整记录和只去掉md5的记录，区分记录元数据变化与正文/位置等变化。其它字段不擅自归一化，不把不同主告警合并。
若FIR先变化，不能归咎同输入求解随机；同FIR而solved变需先核对版本/模型/选项；decisions变需核对report策略；仅报告顺序或md5变化应单列。
输出各阶段计数、首个变化阶段、报告标签计数和guard状态；默认不输出业务路径/函数/正文。可选--details-json仅在公司落更细文件列表/记录索引，不带回。

## 2. 正确性边界
0完整且一致；1检测到变化；2数据缺失/读取失败/冲突或未完成输入。缺少阶段不能把空集合当一致；--through export时pending是正常等待solve。
它定位差异层，不证明两轮源码/版本/配置相同，也不计算漏洞召回率。原始报告数组顺序可能随并行收集变化，不能当作告警集合变化。

## 3. 测试
合成两个WorkDir，依次修改FIR、solved、decisions，首个差异阶段正确；报告换序相等、md5变化单列、正文变化/重复记录增加均发现；缺失/冲突拒绝；默认输出无业务名字/路径。
不修改checker判断或金标准；全部必需回归通过后独立提交。

## 4. 调试与公司
stderr阶段进度不带文件名，结果可--json保存；COMPANY提供复用已有多轮数据的完整命令及只带回计数的模板。
先比较已有数据，不强制再跑两次25分钟；若旧WorkDir被覆盖，需重新保留独立运行快照，工具无法反推旧数据。

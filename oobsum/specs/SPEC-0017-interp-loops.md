# SPEC-0017 函数内解释第三步：循环（不动点、widening、narrowing）

状态：已实现（S7c-1）
来源：`STATUS.md` S7c；06- §6.3 A-33（不动点：分量头上 widening / narrowing，迭代上限）、A-16（循环界的来源标签 `loop`）、A-45（`pointer_stepping` / `type_range_only` 记账）、
D-22（标签）、D-27（`pointer_stepping`、`iter_limit`）；金标准 `LV2-05/Map_ClearWords*`、`LV4-01/Ue_InitTbl`、`LV7-04/Buf_CopyStep`。

## 1. 要解决什么

S7a / S7b 对有回边的函数直接标 `partial:loop_pending`、不产出任何东西（16 个用例里 5 个因此不一致）。最常见的 `for (i = 0; i < n; i++) p[i] = …`
要得到 `i ∈ [0, n − 1]`（标签 `loop`）、访问末端 `[elem, elem·n]`；指针步进 `*p++ = …` 要记账 `pointer_stepping`。

## 2. 设计

### 2.1 求不动点（`core/Interp` 的 `Run`）

1. DFS 找回边；回边的目标是**循环头**。逆后序给每个块编号。
2. **上升**：工作表按逆后序编号取块，算出口状态、沿边 `Assume`、并进后继的入口状态；后继是循环头且已到达过 → **widening**（`Widen(旧, 旧 ⊔ 新)`）。
   入口状态变了才把后继放回工作表。每个循环头至多更新 20 次（A-33），超过 → `status = partial:iter_limit`、不产出 Req（S8c 按"函数没分析完"报 SUSPECT）。
3. **下降（narrowing）**：从上升的结果出发，按逆后序重算 2 遍（每块的入口 = 各入边上一次的贡献之并，不再 widening）。
   上升的结果是后不动点，下降的每一步仍在最小不动点之上，所以结果都是对的。
4. **记录**：用最终的入口状态把每个可达块再走一遍，这一遍才记访问、调用点、账本、`Dump=state`（前面各遍不记，避免重复和中间状态）。

**widening**（值逐个做）：整数下界变小（或不可比）→ 去掉下界；上界变大（或不可比）→ 去掉上界、标签改成 `widen`；指针基址不同 → 未知，同基址 → 偏移做 widening；
内存格只留两边相同的；守卫取交集。不用阈值（以后按需要加，A-33 的阈值表）。

### 2.2 循环头上的条件边：标签 `loop`

`Assume` 知道边的起点是不是循环头：起点是循环头时，收窄出来的上界标签是 `loop`（循环界），否则是 `check`（SPEC-0016）。

### 2.3 区间与确切值的比较也产生原子

`l op X`（`l` 的值是区间 `[lo, hi]`、`X` 是确切值）除了收窄 `l`，还产生关于接口符号的原子：`l < X` → `lo < X`；`l <= X` → `lo <= X`；`l > X` → `hi > X`；
`l >= X` → `hi >= X`；`l == X` → 两条。`Map_ClearWords_OK` 的 `i < (n + 31) / 32`、`i ∈ [0, +∞)` → 守卫 `div(p1 + 31, 32) >= 1`（循环体执行过）。
**在类型范围与已有守卫下已经成立的原子不加**（`div(p1, 32) >= 0` 这种没有信息）——这条也适用于 SPEC-0016 的确切值原子。

### 2.4 比较两边的"忠实"（修订 SPEC-0016 §2.1）

* **忠实**（两边都要）：值落在操作数的 C 类型范围内。区间：上下界都在类型范围内，**或**整个类型范围都在区间里（`u32` 的 `[0, +∞)`）。
  确切值里 `div` / `mod` 的内层也要在类型范围内（内层回绕时除出来的结果不是数学值）。
* **只当"大的一边"可用**：`l < X` / `l <= X` 的 `X`、`X > l` / `X >= l` 的 `X`。无符号的加、乘常数、左移常数、除常数、右移常数、保值的无符号扩展组成的表达式，
  叶子是忠实的局部 / 常数：回绕只会让真实值**变小**（真实值 = 数学值 mod 2^W ≤ 数学值），拿数学值当上界仍然对。`i < (ulBits + 31) / 32` 因此可用；
  `if (off + len <= max)` 的 `off + len` 是"小的一边"，仍不可用（SPEC-0016 的召回取舍不变）。
  只看 FIR 表达式树：先存进局部再比较的（`ulWords = (ulBits + 31) / 32; i < ulWords`）本步不信（SUSPECT），以后给值加来源标记再放开。
* **无符号区间运算的回绕感知**（`Bin`）：无符号的加 / 乘 / 左移得到**区间**、上界不能证明 ≤ 类型最大值 → 下界改成 0（真实值在 `[0, 上界]` 里）。
  `i ∈ [1, +∞)` 的 `i + 1` 因此是 `[0, +∞)`（盖住整个类型范围，忠实），循环计数器从 1 开始也能收窄；下降时上界有了，下界又回到精确值。
  确切值仍按数学值（SPEC-0014 §2.2 的约定），由比较处的忠实判断把关。

### 2.5 访问记账

* 偏移没有上界且来自 widening、地址就是一个指针局部（`*p++`）→ `pointer_stepping`；其余没有上界 → `type_range_only`。
* 账本按（原因, 位置）去重（同一行的读和写只记一条，同金标准）。

## 3. 对召回与误报的影响

循环函数从"什么都不产出"（S8c 会整函数报 SUSPECT）变成逐个访问产出 Req / 账本：证明安全只用不动点上一定成立的事实；widening 丢掉的界一律落到账本（SUSPECT）；
"大的一边"的放宽只在回绕让值变小的运算上成立。迭代超限的函数照旧整函数 SUSPECT。

## 5. 测试

* 单元测试 `InterpTest`（5 组）：`LoopIndexBound`——`i < n`（`end [1, p1]`、`loop`、守卫 `p1 >= 1`，循环头 / 循环体的 `Dump=state` 行）、`i <= n / 32`（无守卫）、
  `i < (n + 31) / 32`（大的一边可用）、`i < n − 1`（`wrap32`）；`LoopSmallSideMayWrap`——`i + 8 <= n` 不收窄 → `type_range_only`；
  `LoopConstantBoundIsSafe`——`i < 4` 下降后 `[0, 3]`、当场证明安全，`i <= 4` 照常生成 Req；`LoopPointerStepping`——`*p++ = *q++` 只记一条 `pointer_stepping`；
  `LoopCallArgument`——实参 `i` 的区间进 `locals`（`loop`）、调用点守卫 `p1 >= 1`。原 `UnknownBaseAndLoops` 的期望有意更新（有回边的函数照常分析）。
* lit `loops.c`：`Dump=state` 看循环头的区间与 `(head)`、`Dump=summary` 看 Req、当场证明安全的 `safe` 行、`pointer_stepping`。
* `engine-check.test` 加入 LV2-05、LV7-04：7 个用例一致。LV4-01 的上传条数已对上，判定要 `Ue_AllocTbl()` 的返回值大小（`ret_new`，S7d）。

## 7. 对主规格的修订

| 条目 | 原写法 | 新写法 |
|---|---|---|
| A-33 | WTO 递归策略；分量头上 widening / narrowing；超限 → 不稳定的值置 ±∞、照常产出 | 工作表按逆后序（后继 0 在前）；循环头 widening（无阈值）、下降 2 遍；超限 → `partial:iter_limit`、不产出 Req（整函数 SUSPECT） |
| SPEC-0014 §2.2 | 无符号加法溢出不考虑 | 确切值仍不考虑；区间结果上界不能证明不溢出时下界改成 0 |
| SPEC-0016 §2.1 | 两边都要忠实（常数或在类型范围内） | 忠实的区间判据放宽（整个类型范围都在区间里也算）、`div` / `mod` 内层要忠实；无符号单调表达式可当"大的一边" |

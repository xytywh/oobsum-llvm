# SPEC-0008 降级：直线代码的指令（06- A-01…A-03、A-05…A-08）

状态：§2.1–§2.6（值、读写、赋值、`return`）已实现（S4c-1）；§2.7–§2.9（调用、结构体拷贝、自增自减、复合赋值、初始化列表、内联汇编）随 S4c-2
来源：`STATUS.md` S4c；06- §6.1 A-01…A-08、§5.2 的例子（`pstTbl[ulIdx].ulId = 0` → `store4 [padd(l0, l1 * 16)] = 0`）、D-31（数组成员以成员为界）、
D-37（柔性数组成员不收窄）、F-08 / A-07（下标访问标 `sub`）。

## 1. 要解决什么

把每个 CFG 块里的语句降成 FIR 指令：每次读内存是一条 `load`（R 访问），每次写内存是一条 `store`（W 访问），标量局部的读写是 `set` / `["l", id]`，
调用是 `call`。地址都写成"基址 + 字节偏移"的表达式（`laddr` / `gaddr` / `padd` / `fld`），这样引擎（S7）在每条 `load` / `store` 上
就能做访问检查、生成 Req。条件边（`assume`）、`&&` / `||` / `?:` 的值在 S5。

## 2. 设计

### 2.1 按 CFG 元素逐个降（A-01）

CSA 的 CFG 把每个子表达式都列成块里的一个元素（与 `debug.DumpCFG` 的 `[B1.3]` 一一对应），求值顺序就是元素顺序。降级按元素顺序处理，
每个表达式的结果按 `Stmt*` 记下来（记忆化），父表达式直接用子表达式记下的结果：

* **纯的**子表达式（常量、读标量局部、算术、地址计算）记成 FIR 表达式树，内联进用到它的地方，不单独成指令。
* **有副作用的**（赋值、调用、`++`）在它的元素位置生成指令，结果落到临时局部（`tmp: true`，名字 `t<k>`），之后引用这个临时局部。
* 读内存（左值转右值）在它的元素位置生成 `load` 到临时局部——于是"读"发生在源码求值的那一刻。
* 读**没取过地址的标量局部**写成 `["l", id]`，引用的是用到那一刻的值；C 的顺序规则保证同一个完整表达式里不会先读后写再用
  （那是未定义行为），所以这样做与源码一致。

一个表达式的结果有三种：**右值**（FIR 表达式）、**标量局部的左值**（局部号）、**内存左值**（地址表达式 + 字节数 + 是否下标访问）。

### 2.2 常量（A-03）

整数类型、没有副作用、`EvaluateAsInt` 能求出来的表达式（字面量、`sizeof`、枚举、宏展开后的常量表达式、带隐式转换的常量）→ `["c", v]`；
值必须严格在 int64 之内，否则 `["unk", "const_overflow"]`（SPEC-0005 §2.3 #5）。

### 2.3 左值 → 地址（A-02）

| 源码 | 结果 |
|---|---|
| 局部（没取过地址的标量） | 标量局部左值 `l<id>` |
| 局部对象（数组、结构体、取过地址的标量）、形参对象 | 内存左值，地址 `&l<id>` |
| 全局、函数内 `static`、`extern` | 内存左值，地址 `&<键>` |
| `a[i]` | 地址 `padd(<a 的值>, i * <元素大小>)`，`sub`；元素大小为 1 时 `padd(a, i)`；VLA 元素 → 偏移 `unk(vla)` |
| `s.f` / `p->f`，`f` 是数组（不是柔性的） | `fld(<基址>, f@<偏移>:<成员大小>)`——以成员为界（D-31） |
| `s.f` / `p->f`，`f` 是柔性数组（`[]`、`[0]`、末尾的 `[1]`） | `padd(<基址>, <偏移>)`——不收窄（D-37） |
| `s.f` / `p->f`，其它成员 | `padd(<基址>, <偏移>)`；偏移为 0 时就是基址；位域：偏移取所在字节，字节数取它跨的字节数 |
| `*p` | 地址 `<p 的值>`，字节数 `sizeof(*p)` |
| 字符串字面量 | `str<长度>` |
| 其它（复合字面量、语句表达式……） | 地址 `unk(<构造名>)` |

`.` 的基址是左边对象的地址，`->` 的基址是左边指针的值。偏移取 `ASTRecordLayout`（目标 ABI）。

### 2.4 右值（A-03）

| 源码 | FIR |
|---|---|
| 左值转右值：标量局部 | `["l", id]` |
| 左值转右值：内存 | `load<字节数> [地址]` 到临时局部（下标访问带 `sub`）；**结构体按值读同样生成 `load<结构体大小>`**（一次真实的 R 访问），值记 `unk(struct_by_value)` |
| 数组退化 | 数组的地址 |
| 函数名退化 | `&<函数键>`（`faddr`） |
| 整数转换（宽度或符号变了） | `cast(w, s, v)`；没变就是 `v` |
| 转成 `_Bool`（整数、指针） | `v != 0`（`cmp ne`，无符号） |
| 指针之间的转换、`void *` 互转 | 原值（FIR 里没有指针类型转换） |
| 空指针常量 → 指针 | `0` |
| 指针 → 整数 / 整数 → 指针（非 0） | `unk(ptr_to_int)` / `unk(int_to_ptr)` |
| 浮点相关 | `unk(float)` |
| `+x` / `-x` / `~x` / `!x` | `x` / `(0 - x):<类型>` / `(<类型>)~x` / `!x` |
| 整数的 `+ - * / % << >> & \| ^` | `(a op b):<结果类型>`（带宽度与符号的回绕形，SPEC-0005 §2.3 #1） |
| 指针 `± i` | `padd(p, i * <元素大小>)` / `padd(p, i * -<元素大小>)`（数学整数） |
| 指针 − 指针 | `psub(p, q, <元素大小>)` |
| 比较 | `a <op><s\|u> b`，有无符号取操作数类型（指针按无符号） |
| 逗号 | 右边的值 |
| `&&` / `\|\|` / `?:` 当值用 | **S5**；本步 `unk(cond_value)` |
| 其它 | `unk(<构造名>)` |

### 2.5 赋值与声明

* `x = e`：标量局部 → `set l<x> = e`；内存左值 → `store<字节数> [地址] = e`（下标访问带 `sub`）。表达式的值是 `e`。
* 声明带初始化：标量 → 同上；数组 / 结构体的初始化（初始化列表、字符串）→ S4c-2。函数内 `static` 的初始化不在函数体里（只执行一次），不降。
* 结构体整体赋值 → S4c-2（A-06）。

### 2.6 `return`

`ret <值>`；`void` 函数 `ret`；返回结构体 → `ret unk(struct_by_value)`。

### 2.7 调用（S4c-2，A-05）

直接调用 → 函数键；`__builtin_memcpy` 等 `__builtin_<libc 名>` → `F:<libc 名>`；`__builtin_expect(x, c)` → `x`（不生成调用）；
间接调用 → `["ind", <被调表达式>]`。实参按值；结构体按值传参 → `unk(struct_by_value)`。返回值非 `void` 时落到临时局部。`ord` 是函数内调用点的序号（从 0 起）。

### 2.8 其余有副作用的构造（S4c-2）

* `++x` / `x++` / `--x` / `x--`：整数按类型回绕加减 1，指针 `padd(p, ±元素大小)`；后缀形先把旧值存进临时局部。
* `x op= e`：读旧值、算新值、写回。
* 结构体整体赋值 `a = b` → `call __oobsum_copy(&a, &b, sizeof)`（A-06，内置访问模型）。
* 初始化列表：逐个标量元素按偏移 `store`（每个对象至多 64 个，多出的不降，值未知）；字符数组用字符串初始化 → 不降（内容未知，P2 字符串长度）。
* 内联汇编：输出操作数是标量局部 → `havoc(inline_asm)`；是内存 → `store<字节数> [地址] = ?`。
* 去掉 `body_pending`。

### 2.9 不支持的构造（A-08）

不认识的表达式 → `unk(<Clang 的类名>)`；不认识的语句 → 忽略（它的子表达式本来就是单独的元素，已经降了）。函数照样导出（全函数性）。

## 3. 对召回与误报的影响

还没有引擎，不产生判定；默认运行不降级。设计上的召回考虑：未知一律写 `unk`（以后只会导向 SUSPECT），不认识的构造不跳过整个函数；
柔性数组成员不按成员收窄（宁可漏判，也不误报出"越过成员末尾"，D-37）；位域写入的字节数取它实际跨的字节数（不按声明类型的大小，避免在记录末尾误判越界）。

## 6. 调试

`Dump=fir`（`DumpFilter=^函数名$`）对照 `-analyzer-checker=debug.DumpCFG`：FIR 的每条指令对应 CFG 里的某个元素；`load` / `store` 的个数就是
源码里内存读写的个数。

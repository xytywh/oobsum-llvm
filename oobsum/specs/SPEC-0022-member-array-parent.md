# SPEC-0022 经形参访问成员数组：成员边界与外层对象边界都查

状态：已实现
来源：引擎接进 checker 时 `run.py csa` 发现的漏报（LV7-03：TP 被证明成"安全"）；06- F-01 / F-02（`off(f) + sizeof(f) <= ext(p)`）、D-31（成员数组以成员为界）、
SPEC-0014 §2.1（`fld` 收窄成 `p0->aucBuf`）；SPEC-0001（只有证明了安全才是 SAFE）。

## 1. 要解决什么

S7a 把"形参所指结构体里的成员数组"`pstMsg->aucData[i]` 的基址换成成员本身（D-31：对象 `p0->aucData`、大小是成员的 12 字节），**外层对象的边界丢了**。
LV7-03：`MSG_S`（16 字节）按指针套在 8 字节的缓冲区上，`aucData[6]` 在成员里（7 <= 12），但在对象外（4 + 6 + 1 = 11 > 8）——引擎只查成员，
在 TP 的调用点判成 SAFE。这是把越界证明成安全，违反召回优先。

## 2. 设计

成员数组的指针记住外层对象（`*pK`、`ext(pK)`）与成员在结构体里的偏移；每次经它的访问生成**两条**检查：成员边界（`have` = 成员大小，D-31，原样）
与外层对象边界（`have = ext(pK)`、偏移 = 成员偏移 + 下标偏移，F-02）。两条各自走当场证明 / Req / 账本。

不在本步：把成员指针当实参传下去（`Om_SaveCfg(pstMsg->aucBody, …)`）时，调用点记录只能写一个对象（`p0->aucBody`、1024），外层对象的边界同样丢了；
要在实参格式里加"外层对象"（摘要格式修订），记在 STATUS 的已知问题里。

## 3. 对召回与误报的影响

补上漏报（LV7-03 TP：外层对象 11 > 8 → L1）；只多检查、不少检查。外层对象边界在入口上是 `entry_unproven` / `typed_field`（对象就是形参所指的结构体）。

## 4. 实现位置

`core/Interp.{h,cpp}`：`PtrVal` 的 `hasParent` 等字段、`fld` 时记下、`Access` 对成员访问再按外层对象查一遍。

## 5. 测试

* 单元测试 `InterpTest.ParamFieldsAndMemberArray`：成员数组的写多一条 `*p0` 的 Req（期望有意更新）。
* lit `member-array.c`：LV7-03 的写法，`Dump=summary` 两条 Req。
* 金标准不受影响（16 个用例里没有本地访问形参的成员数组）；`replay.py`、`engine_check.py` 不变。

## 6. 调试

`Dump=summary` 看两条 Req（对象 `*p0` 与 `p0->成员`）。

## 7. 对主规格的修订

| 条目 | 原写法 | 新写法 |
|---|---|---|
| D-31 | 成员数组访问以成员为界 | 以成员为界，**并且**外层对象的边界也要满足（F-02） |

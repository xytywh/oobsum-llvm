# SPEC-0042 汇合时按各自路上的守卫求常数界（钳位写法不再丢界）

状态：已实现
来源：探针（SPEC-0041 之后）：`if (i > 15) { i = 15; } p[i] = 0;` 报 SUSPECT `type_range_only`（应为 SAFE）；`i = (i > 16) ? 16 : i;` 报 SUSPECT（应为 POSSIBLE）。
业务代码里"`if (len > MAX) { len = MAX; }` 再拷贝"非常常见，这类误报会很多。06- A-15（合并）、SPEC-0023（符号界的合并：在两边共同成立的守卫下比较）。

## 1. 要解决什么

钳位的两条路：一条 `i` 不变、守卫 `i <= 15`；另一条 `i = 15`、守卫 `i >= 16`。共同成立的守卫为空，`min(i, 15)` / `max(i, 15)` 都比不出来
→ 合并成 Top（`imprecise_join`）→ 访问只剩类型范围。

## 2. 设计

`JoinInt` 的某一端（下界 / 上界）在共同环境下比不出来时，**各自在自己那条路的守卫与类型范围下**求这一端的常数界（`SymEnv::RangeOf`），
两边都求得出来就取 `min` / `max` 作为合并后的那一端；标签取两边来源标签里更差的（D-22 的合并顺序：一边来自守卫、另一边是常数 → `guard` 等代码给出的界）。

每边的值在它那条路上都落在求出的界内，所以合并的区间包含两边所有的值（可靠）。只在原来会丢掉这一端时才用；能在共同环境下比出来的照旧（符号界优先）。
汇合点的各自环境由 `Join` 的 `envOf`（已有）分别对两边的守卫建；没有 `envOf` 的调用不变。

## 3. 对召回与误报的影响

**误报减少**：钳位、`?:` 选较小值等写法证明 SAFE 或判出 POSSIBLE（原来是 SUSPECT）。**召回**：只有证明了界才收紧，界内照常判 L1 / L2；
回归用例守住钳位到 16（越界）时仍报。

## 4. 实现位置

`core/Interp.cpp`：`JoinInt` / `JoinValue` 加两边的环境，`Join` 传入 `envOf(a.guards)` / `envOf(b.guards)`。

## 5. 测试

* lit `join-clamp.test`：`if (i > 15) i = 15;` → SAFE；`i = (i > 16) ? 16 : i;` → POSSIBLE；`if (len > 8) len = 8;` 后 `memset_s(buf16, 16, 0, len)` → SAFE；
  对照：钳到 20 → POSSIBLE / DEFINITE（不是 SAFE）。
* `run.py csa` 无回退；`replay.py`、`engine_check` 不回退。

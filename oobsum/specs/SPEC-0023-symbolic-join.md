# SPEC-0023 汇合、收窄时用类型范围与守卫比较符号界

状态：已实现（S8c-2 的第一项）
来源：`run.py csa` 的对照：LV3-05 TP 期望 L1，引擎只在 `Name_Pad` 里报了 SUSPECT（`type_range_only`）；06- A-15（合并）、A-17（带 `min` / `max` 的界）、A-30（收窄）、
SPEC-0014（`JoinInt`）、SPEC-0016 / 0017（`Narrow`、循环）。

## 1. 要解决什么

`for (i = 0; i < n; i++) p[i] = ' '; p[i] = '\0';`：循环头汇合 `i = 0` 与 `i ∈ [1, p1]` 时，上界 `0` 与 `p1` 的差不是常数，`JoinInt` 把上界丢成 +∞；
出口 `i >= p1` 收窄下界时，`0` 与 `p1` 同样不可比，`Narrow` 留了原来的 0。于是 `p[i]` 的偏移是 `[0, +∞)`、记账 `type_range_only`，
而 golden 的推导是"退出时 `i == ulLen`"、TP 上 17 > 16 判 L1。

## 2. 设计

两个界 `x`、`y` 的差不是常数时，用**类型范围与两边都成立的守卫**判 `x <= y`（`EntailsLe0(x − y)`，SPEC-0011）：

* **汇合**（`Join`）：`min(lo_a, lo_b)`、`max(hi_a, hi_b)` 能比出大小就取对应的那一个，比不出才丢。守卫用两边守卫的交集（A-15，汇合后成立的只有它们）。
  `max(0, p1) = p1`（`p1` 是无符号形参，`p1 >= 0`）。
* **收窄**（`Narrow`）：新界与原界取更紧的那个时同样先判，环境是这条边上的状态（含这条边之前的守卫）。`i ∈ [0, p1]` 经 `i >= p1` → `[p1, p1]` → 确切值 `p1`。

只在"证明了 `x <= y`"时才取，比不出照旧丢界（落到账本），不会把界取错。

**忠实判断里区间的界只查是否落在类型范围内**（修订 SPEC-0017 §2.4）：确切值仍要求 `div` / `mod` 的内层不回绕（确切值要等于真实值）；
区间的界是收窄时按"忠实 / 可当大的一边"的规则造出来的可靠界（上界只会大于等于真实值），内层回绕只让真实值更小，不必再查内层。
否则循环头更准之后（`[0, div(p1 + 31, 32)]`）反而通不过忠实判断、不再收窄。

## 3. 对召回与误报的影响

精度提高：LV3-05 TP 从 SUSPECT（在被调者里）变成调用点上的 L1。区间只会更准、不会变成不含真实值（取的都是可证的更大上界 / 更小下界）。

## 4. 实现位置

`core/Interp.cpp`：`ProvablyLe`、`MinOpt` / `MaxOpt` / `JoinInt` / `JoinValue` 带比较环境（`Comparer`）、`Join` 先求守卫交集、再用 `envOf` 建环境、
`Narrow` 的 `tighter`、`FaithfulAs` 的区间判断。

## 5. 测试

* 单元测试 `InterpTest.LoopExitEquality`：LV3-05 的写法，循环后 `p[i]` 的末端是 `p1 + 1`；`InterpTest` 已有的循环用例不变。
* lit `loops.c`：循环头 `[0, p1]`；`Pad`（LV3-05 的写法）循环后的写末端 `p1 + 1`。
* `run.py csa`：LV3-05 TP 变成 DEFINITE（通过），其余不变；基线有意更新。
* **对照尺子的修订**（SPEC-0002 §2.4）：LV3-05 原来在 `Name_Pad:30` 的 SUSPECT，现在是 TP 调用点上的 DEFINITE（同一次访问报在了汇合点、标签更强），
  按位置比对会被当成"回退"。改成：基线里报过的访问，这次若是某条报出的判定的调用链终点，也算仍报出（`run.py` 读判定的 `chain` 末项）。

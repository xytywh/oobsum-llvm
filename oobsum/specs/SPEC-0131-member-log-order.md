# SPEC-0131 成员实参日志回归按字段核验，消除仓库路径导致的假失败

状态：已实现
来源：用户2026-11-05公司lit为115通过/1失败，失败member-arg.test；目前未带回具体失败段。本地原路径通过，复制同一自有用例到其它绝对路径后复现DUP第二条FileCheck失败。

## 1. 要解决什么
Reporter按位置/标签/指纹排序。Body_Clear是static函数，访问函数键包含绝对文件路径的哈希，改变仓库路径会改变指纹和同位置日志先后。
member-arg.test却固定要求先出现已报出的type_range_only，再出现未报出的entry_unproven，尽管两条的标签、报出状态和dup_of引用均正确。
这是测试把日志展示顺序当成语义顺序；保持F-34函数键和F-35确定性，不修改规则来迎合测试。

## 2. 设计
* 保留所有摘要字段、告警位置/数量、SAFE/DEFINITE/SUSPECT及SuspectReasons后备报告的既有断言。
* Dump=decisions先保存完整stderr，Python按JSON筛选F:Entry_Msg，要求恰好两条、对象分别为成员与外层。
* 核验两条SUSPECT的原因、读写/深度、报出状态；外层未报原因duplicate_access、dup_of准确引用成员fp，两条指向同一次访问；不依赖日志前后顺序。
* 对真实日志反序后仍须通过；损坏dup_of、缺失记录、重复记录、错误标签或错误报出状态必须失败，避免仅仅放宽匹配。
* 用不同路径的源码副本重跑并核验；同样源内容、不同路径允许fp与展示顺序变化，判断语义不应变化。

## 3. 对召回与误报的影响
无。仅修复lit断言；不改引擎、标签、报告策略、指纹、日志顺序、用例源码或金标准。

## 4. 实现位置
member-arg.test、Inputs/member/check_log.py；COMPANY与STATUS记录公司失败及本地复现证据。

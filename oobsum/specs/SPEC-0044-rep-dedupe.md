# SPEC-0044 同一调用点同一次访问的判定只报一条（成员界与外层界）

状态：已实现
来源：探针（结构体数组、联合体）：`t->astEnt[4].ulId = 1`、`u->auc[4] = 0` 这类成员数组越界，在同一调用点报两条 DEFINITE——一条按成员的界
（对象名写不出来，显示 `'?'`），一条按外层对象（SPEC-0022：成员、外层都查）。SPEC-0036（入口账本按访问去重）的同一做法用到 L1 / L2。

## 1. 要解决什么

一次越界、两条告警，其中一条的对象名是 `'?'`：复核的人看到的是重复、而且更难懂的那条。

## 2. 设计

* 引擎（`core/Engine`）记调用点判出的 L1 / L2 时，按 **（函数、调用点、访问的函数键与位置、读写、方向）** 分组；组里挑一条主判定：
  DEFINITE 优先于 POSSIBLE；同级时对象名写得出来的（不是 `?`）优先；再按出现顺序。其余的记 `dupOf` = 主判定的指纹。
* 策略不变（`ClassifyBatch`，SPEC-0036）：主判定报出了，`dupOf` 的不报（`duplicate_access`）；主判定被过滤（`InlineDepth` 等）时这条按自己的规则定。
* 判定日志里每条都在。

## 3. 对召回与误报的影响

同一调用点同一次访问至少报一条（主判定照原规则），不丢访问；去掉的只是重复告警。级别取更重的那条（DEFINITE 优先），不会因为去重把 DEFINITE 降成 POSSIBLE。

## 4. 实现位置

`core/Engine.cpp`（调用点 L1 / L2 判定的分组）。

## 5. 测试

* lit `rep-dedupe.test`：结构体数组越界、元素成员数组越界、联合体成员越界 → 每处一条 DEFINITE（对象名不是 `?`）；`Dump=decisions` 里另一条带 `dup_of`、
  `duplicate_access`。
* `run.py csa` 无回退。

## 6. 调试

`Dump=decisions`（`dup_of`）。

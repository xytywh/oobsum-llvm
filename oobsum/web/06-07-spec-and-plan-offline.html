开发方式：两个环境的闭环

 我（沙箱：上游 LLVM 14.0.6 / clang-14）                         你（fork：/usr1/BXPlugin）
 ─────────────────────────────────────                         ─────────────────────────
 写代码 → 插件构建 → T-01 单测 → cases 全量 T-03                      解包覆盖 → make -j16

  • 节奏：每周两次交付（周二、周五），每次一个完整代码包（oob-summary-v0.N）+ 中文提交信息（csa-checker-dev 格式，scope rb.enhance.ipa.OobSummary）+ 验证命令 + 沙箱结果表。

  • 沙箱结果与 fork 不一致时：以 fork 为准，我在沙箱里补一个复现用例，进 T-03 / T-07。
  • 每次交付前我必须跑完：插件构建无告警、T-01 全过、T-03 不回退（已通过的入口不得变成失败）、T-07 无崩溃、规范检查无 FAIL。

0.1 本版新增的设计决策（详见 §12，需要你点头）

# 决策 一句话理由
D5′ 跨 TU 改为方案 B：一遍导出 → 离线求解 → 一遍出告警（替代 v3.7 建议的多轮扫描） 有了 D9，B 的额外工作只剩序列化；B 的遍数固定为 2，与调用链跨多少文件无关；多轮的代价要看探针统计，B 没有这个不确定性
D9 引擎跑在自己的轻量中间表示 FIR 上，不直接跑 clang::CFG 引擎与 Clang 解耦：可单测、可离线求解、可直接喂给 AI；Clang 相关的复杂度集中在一处（降级）
D10 落盘用 JSON（llvm::json），查询库（SQLite）由 Python 驱动生成；C++ 侧不引入任何第三方库 不动 xir 的依赖；跨语言可读（01- R5）；多进程写不同文件、无锁
D11 checker 只挂 check::ASTDecl<TranslationUnitDecl>，不挂任何路径敏感回调 沙箱实测：多挂一个空的 EndOfTranslationUnit，每个函数都会跑一遍 ExprEngine实测数据
D12 告警报在汇合点的调用表达式上；跨文件的 trace 写进 note 文本 CSA 的 note 只能指向本 TU 可见的文件，被调者在别的 .c 里时无法定位
D13 函数 / 全局用自定义键（外部链接用名字，内部链接带定义文件），不用 USR C 没有重载，名字即可；不依赖 clangIndex；头文件 static inline 可跨 TU 去重
D7 新 checker：rb.enhance.ipa.OobSummary（类 OobSummaryChecker） 跨 TU 规则按 csa-checker-dev 约定须与你确认包；它不用 CSA 的 IPA，ipa 取值不影响它
06- §1

范围

1.1 一句话

一个只做语法遍历的 CSA checker 把每个函数降成 FIR；一个与 Clang 无关的抽象解释引擎自底向上给每个函数算出越界摘要 （前置条件 Req、效果 Eff、已判定 Rep、账本 Open），在调用点代换、逐层上传，在大小和访问都已知的那一层（汇合点）判定； 判定出的越界按现有告警格式报出，只报现有规则看不到的（> inlineDepth 层，CSA 盲区例外）。

1.2 P0 必须支持的场景（验收口径）

类别 场景（04-） 用例（cases/） 要求
年内承诺 26 个：Lv1–Lv4 全部 + S5.1 32 个用例：LV1-01…08、LV2-01…09、LV3-01…05、LV3-08…10、LV4-01…05、LV5-01、LV5-06，以及 LV3-07 的 TN TP 按期望级别报出（L1 / L2），TN 不报

运行形态总览

compile_commands ─▶ rb.enhance.ipa.OobSummary ──▶ WorkDir/fir/<tu>.json   （每个 TU 一份 FIR + 全局声明）

  Phase=inline（默认值）：单个 TU 内一次做完 ①②③（跨 TU 的被调者视为未知）。
  所以 csa-checker-dev 约定的"单文件 bxen 命令"不加任何参数就能跑同文件内的多层链。

为什么从多轮扫描（方案 A）改成方案 B推断：

A：多轮 TU 扫描 + 工作表（v3.7 建议） B：一遍导出 → 离线求解 → 一遍出告警（本版）
解析遍数 轮数 ≈ 调用链上跨文件切换的次数；同一 TU 可能被重复解析多次 固定 2 遍（export 全量；report 只跑有告警的 TU）
代价的不确定性 取决于真实代码的调用图形态，要先量（探针 probe_stats.py 的"TU 分析总次数 / TU 数"） 无
新增基础设施 每轮的导入文件、合并、工作表、跨轮去重 FIR 序列化（llvm::json）、求解入口
跨 TU 递归 / 调度 按轮次近似 全局 SCC，和同 TU 一样处理
2027 增量分析 每次都从解析开始 只重导出改过的 TU、只重算受影响的 SCC
给 AI / 查询（05- 方案 E、G） 另行导出 FIR + 摘要本身就是

前提是 D9（引擎跑在 FIR 上）：两种方案共用同一个引擎，只是编排不同。A 保留为回退方案（§7 的 X-08），不在 P0 实现。

功能需求

3.1 检测对象

编号 访问形态 生成的安全条件（字节） 备注
F-01 数组下标读 / 写 a[i]、p[i]、s.arr[i]、p->arr[i]、g.arr[i] off + size ≤ ext(base)，且 off ≥ 0 结构体成员数组以成员为对象（子对象边界，01- §3.1 #2–#7、#11）
F-02 指针解引用 *p、*(p + k)、p->f（p 指向的对象可能比类型小） off(f) + sizeof(f) ≤ ext(p) 覆盖"按大结构体访问小对象"（LV1-05、LV4-02）
F-03 memcpy_s / memmove_s(dest, destMax, src, count) destMax ≤ ext(dest)；count ≤ ext(src) count > destMax 运行时被拦，不算越界（01- §3.7.3）
F-04 memset_s(dest, destMax, c, count) destMax ≤ ext(dest)
F-05 libc memcpy / memmove / memset n ≤ ext(dest)；n ≤ ext(src) 代价很小，顺带支持
F-06 模型表里配置的其它访问函数（内部封装） 按配置（§4.4） 清单由你提供（07- 输入 I8）
F-07 循环里的访问 下标取循环后的区间（阈值 widening + narrowing） 任何循环都必须产出结果，不得 unsupported
F-08 指向数组中间的指针再下标 p = &a[2]; p[j]、p = a + k; p[j] 基址 a、偏移 2·elem + j·elem CSA 盲区 #21：打 csaBlindSpot，不做层数过滤（01- §0.1）

ext(x) 的含义与 05- §2.1 相同：从指针 x 往后还能访问的字节数（对象大小 − 偏移）。负偏移（off < 0）同样是越界，按同一套级别判定。

3.2 判定与级别

在汇合点，对代换后的条件 need ≤ have（need = off + size，have = ext(base)）：

编号 结论 判据 去向
F-10 Safe need 的上界 ≤ have 的下界（区间或经守卫蕴含，§6.5） 丢弃
F-11 L1 need 的下界 > have 的上界（对所有取值都越界） 报（Definite）
F-12 L2 下界不越界、上界越界，且上界来自代码：校验、掩码、%、分支常量、循环界、被调者返回值范围、守卫 报（Possible）
F-13 上传 还含当前函数的接口符号 代换成当前函数的 Req，depth + 1
F-14 记账 到入口仍含符号；或上界只来自类型范围（UINT16 的 65535）、widening 的 ∞、不透明非线性项、读自内存内容的无约束值 不报；账本记原因

上界的来源标签随值一起传播（§6.2），F-12 只认标签集合 ⊆ {check, mask, branch, loop, ret, guard, const} 的上界。 F-15：S2 级（符号可疑）P0 不输出。F-16：ReportL2=false 时只报 L1（G3 的"精度不够先只出 L1"预案）。

3.3 只报现有规则看不到的（通道分工）

  • F-20：每条判定带两个层数：depth（访问点到汇合点经过的调用边数）与 effDepth（判定用到的大小、偏移、长度里，经效果向上传得最远的层数）。 报告条件：max(depth, effDepth) > InlineDepth（默认 2，取你们现有规则的 inline 上限，07- 输入 I6）。 理由：现有规则要 inline 到大小和访问两侧才能判，任何一侧超出 inline 深度它就看不到推断。
  • F-21：csaBlindSpot 的判定（F-08、二维数组字段 [P1]）不做层数过滤。
  • F-22：EvalMode=true 时不过滤，全报并在消息里带层数，用于和现有规则逐条对比（03- T1-5）。

3.4 告警内容

  • F-30 位置：汇合点函数里那次调用的调用表达式（被判定的条件从这里进入）。depth = 0（只在 F-21 / F-22 时才会报）报在访问点本身。
  • F-31 BugType（英文，csa-checker-dev 约定；category 只用于展示）： "Out-of-bound access via call chain (definite)"、"Out-of-bound access via call chain (possible)"，category "Memory error"。
  • F-32 消息（英文模板，{} 为占位）：

L1: Definite out-of-bound {write|read} through a {N}-level call chain: up to byte {need} of {object} ({size} bytes) is accessed L2: Possible out-of-bound {write|read} through a {N}-level call chain: up to byte {needHi} of {object} ({size} bytes) may be accessed; the bound comes from {source}

{object} 是汇合点处对象的描述：变量名（'aucName'）、成员路径（'pstCtx->aucBuf'，结构体名按 typedef 反查）、 堆对象（heap object allocated at alm_top.c:42）；{size}、{need} 可以是符号式（LV2-04：4*ulNum+4 对 4*ulNum）。 * F-33 trace（note）： ① 一条总链 note，锚在告警位置：Call chain: Ue_Setup (ue_init.c:80) -> Ue_InitTbl (ue_init.c:60) -> Ue_InitOne (ue_tbl.c:40): write of 4 bytes at offset 16*ulIdx； ② 链上每一跳、访问点、大小来源（分配点）里位于本 TU 可见文件的，各一条 note 指向那一行； ③ 不在本 TU 的只出现在 ① 的文本里（D12）。 * F-34 指纹：xxHash64("OobSummary|" + level + "|" + 汇合点函数键 + "|" + 访问函数键 + "|" + R/W + "|" + 访问序号 + "|" + 对象描述)， 不含行号（01- §3.10）；访问序号＝该访问在其函数 FIR 里同类访问中的序号。同一指纹全工程只报一次。 * F-35 确定性：同一 TU 的告警按（文件、行、列、指纹）排序后发出（csa-checker-dev 约定）。

D-10 类型 t：{k:int,w,s}、{k:ptr,to}、{k:arr,n|null,elem}（n 为 null 即柔性 / 不完整）、{k:rec,id}、{k:void}、{k:other,size}。 记录类型放模块级 records 表，字段带字节偏移（按被分析 TU 自己的目标 ABI 算，即 ILP32 与否以 cdb / fork 为准，§5.4）。

6.1 降级：Clang → FIR（lower/，只有这一层碰 Clang）

编号 规则
A-01 CFG 用 AnalysisManager::getCFG(fd)（与 CSA 同一份）。按块号、块内元素顺序降级；每个子表达式的值按 Stmt* 记忆，纯子表达式内联成 Expr 树，有副作用的（调用、赋值、++）生成指令并落到临时局部
A-02 左值降成地址表达式：局部对象 → laddr；全局 → gaddr；a[i] → padd(基址, i × 元素大小)；数组成员（. / ->）→ fld；标量成员 → padd(基址, 偏移)；*p → p；字符串字面量 → str
A-03 右值：未取过地址的标量局部 → ["l", id]；其余左值转右值 → load（同时是一次 R 访问）；整数转换 → cast；指针类型转换在 FIR 里消失（偏移都按字节）；数组退化 → 首元素地址；sizeof / 枚举 / 常量表达式 → EvaluateAsInt 成常数；浮点 → unk
A-04 ?:、&&、|| 作为值使用时，在两个前驱块末尾补 set tmp，汇合块引用 tmp
A-05 调用：直接调用 → 函数键；__builtin_memcpy 等映射到 libc 名；__builtin_expect(x, c) → x；间接调用 → ["ind", E]
A-06 结构体整体赋值 a = b → 一次 call __oobsum_copy(&a, &b, sizeof)（内置访问模型：W / R 各 sizeof 字节）；结构体按值传参 → 实参 unk(struct_by_value)
A-07 下标访问在 load / store 上带 sub: true；引擎据此识别 F-08 的盲区形态（指针来自 &a[k] / a + k、再用非常量下标）
A-08 不认识的构造 → havoc 或 unk，带原因；函数照样导出（全函数性）
A-09 块数 > MaxBlocks 的函数只导出签名与 flags: ["cfg_too_large"]，求解时 skipped:cfg_too_large

6.2 抽象域（core/，不依赖 Clang）

  • A-10 整数值 AbsInt = [lo, hi]，lo / hi 是 界：LE（接口符号的线性式 + 不透明项）、min(c, LE) / max(c, LE)、±∞。 每个界带来源标签集合 src ⊆ {const, check, mask, branch, loop, ret, guard, type, widen, data, unknown}（F-12 用）；另带 via（经效果传了几层，饱和于 255）。
  • A-11 指针值 PtrVal = (base, off: AbsInt 字节, maybeNull, via)。base 种类：Param(i)、ParamField(i, path)、Global(K)、GlobalPtr(K)、Local(id)、 Sub(父, 偏移, 大小, 名字)（数组成员子对象）、Alloc(调用点, size: LE)、Str(len)、Ret(调用点)（大小未知）、Func(K)、Unknown(原因)。 have(PtrVal) = size(base) − off，其中 size(Param(i)) := ext(p#i) 并约定 off 相对形参指针。
  • A-12 内存格 cells: (base, 常量偏移, 大小) → 值。形参可达的格第一次读到时取初值符号 p#i->o:s（两次解引用以内）；局部对象的格初值未知； 非常量偏移的写 → 失效该 base 上重叠的格；经 Unknown 基址的写 → 失效所有非局部对象的格（按类型细分留 P1）。
  • A-13 定义式 defs: 局部 → Expr（只含局部与接口符号，深度 ≤ 4）：记录"rem = total − off"这类关系，操作数被重新赋值时失效。用于 §6.4 的同类项抵消（01- §3.6）。
  • A-14 守卫 guards：至多 8 个原子 LE ≤ 0（只含接口符号），先进先出。来源：assume 边（把局部的确切符号值代进去后仍含接口符号的比较）； 带符号界的区间非空约束（i ∈ [0, p#1−1] ⇒ p#1 ≥ 1）。
  • A-15 合并：值逐点合并；两个界差为常数时取数值较大 / 较小者；一个是常数一个是 LE 时取 max(c, LE) / min(c, LE)；其余 → ±∞ 并带 imprecise_join。 指针同 base 合并偏移；不同 base → Unknown(base_join)；一边是空指针常量 → maybeNull。守卫取交集；定义式保留两边相同的。
  • A-16 widening：在 WTO 分量头，前 2 次合并照常，之后按阈值外推：阈值集 = 函数里所有比较中的常数 c 的 {c−1, c, c+1}， 以及与接口符号式比较时的 {E−1, E, E+1}；没有阈值可用才到 ±∞（src 加 widen）。narrowing 2 轮。
  • A-17 化简：min(max(c, x), x + d)（d ≤ 0）→ x + d 等少量规则（与 Infer Bound 的 MinMax 化简同类）；化简失败保留原式。

6.4 访问检查与 Req 生成

对一次访问（kind、地址 P、字节数 S）：

  1. A-40 符号形：把 P 求成 (base, offExpr)、S 求成 sizeExpr，其中 offExpr / sizeExpr 是局部与接口符号的表达式（按定义式展开，深度 ≤ 4），先不代区间。
  2. A-41 化简：D = offExpr + sizeExpr − have(base) 线性化，同类项抵消（局部也参与抵消，LV3-07 的 ulOff）。
  3. A-42 代区间：D 里剩下的局部换成它们的界（系数为正取上界、为负取下界），得到 D 的上界 U 与下界 L（只含接口符号），并记下所用界的来源标签； 另对 offExpr 求下界，检查 off ≥ 0。
  4. A-43 当场判定：U、L 不含符号时按 F-10…F-14 判；depth = 0，判出的进 reps（只有 F-21 / F-22 时才会报出，其余被 F-20 过滤，但照样入 reports.json 并标 filtered）。
  5. A-44 生成 Req：含接口符号时，先用守卫判蕴含（§6.5）：U ≤ 0 成立 → 安全，丢弃；否则生成 Req：have、lo、hi、size、hi_src、 与 Req 符号相关的守卫原子、访问位置与序号、depth = 0、blind（A-07）。同一 have、同一访问位置的 Req 只留最强的一条。
  6. A-45 记账：have 无法表示（Ret / Unknown base、未知大小的分配）→ 记账 alloc_size_unknown / 对应原因；上界只来自 type / widen / data → type_range_only / pointer_stepping；含 nonlinear → nonlinear。

6.5 蕴含判定（守卫 ⇒ 条件）

A-50：判定 U ≤ 0 是否在守卫 G 与符号取值范围 R（无符号形参 ≥ 0、ext(·) ≥ 0、类型范围）下恒成立：

  1. 只用 R 求 U 的上界 ≤ 0 → 成立；
  2. 对每个守卫原子 g、U 与 g 共有且系数同号的符号 s：U′ = U − (a_s / b_s)·g（有理系数），U′ 的上界 ≤ 0 → 成立；
  3. 再对守卫原子两两组合做一次第 2 步（至多 28 对）；
  4. 否则"判不了"。

A-51：L1 的判定对称：L > 0 在 G 与 R 下恒成立。A-52：判定只用线性推理与区间，不调 SMT，代价有界。

6.6 调用点（05- §3.1 的五步）

步 编号 规则
① 取摘要 A-60 直接调用 → 求解阶段已算好的摘要（SCC 逆拓扑序保证被调者先算）或模型；间接调用 → 被调表达式是定义式为 faddr 常量的局部时当直接调用（S9.1 尽力），否则记账 fptr
② 代换表 A-61 p#i ↦ 实参的值与符号形；ext(p#i) ↦ have(实参指针)；p#i->o:s ↦ 调用方在（实参 base，实参偏移 + o，s）处的格值——实参 base 是调用方形参时改写成调用方的字段符号（路径加一层，超过两次解引用则未知）；g:K ↦ g:K
③ 代换并判定 A-62 每条 Req：代换 have / lo / hi / size / 守卫，按 §6.4 第 2–6 步判定：安全 / L1 / L2 / 上传（depth + 1，path 前加本调用点，eff_depth 取所用值的 via 最大值）/ 记账。守卫代换后为假 → 这次调用不会走到访问 → 安全；守卫判不了且含调用方局部 → 不报（避免误报），记账 entry_unproven
④ 效果 A-63 ret_new → 结果为 Alloc(调用点, 代换后的大小)、via + 1；ret_ptr / ret_int → 代换后的值、src 加 ret；out_* / field → 写调用方的格；invalidate → 失效调用方相应的格；global → P0 只失效调用方对该全局的缓存
⑤ 条件效应 A-64 ret_cond 挂在接收返回值的局部上；之后在该局部上的 assume 选中 ret == c 那一侧时，把代换后的原子加入守卫并收窄实参对应的局部（LV4-06 if (Check(id) != OK) return;）

A-65 模型：分配器 → Alloc(调用点, size)、via = 0；访问类 → 按条件生成访问检查（§6.4）；纯函数 → 不失效、结果未知。 A-66 未知函数（无摘要、无模型）：结果未知（原因 unknown_callee / not_exported / not_in_tu）；经指针实参可达的格失效。

6.7 效果生成（函数出口）

A-70：返回值 → ret_new（base 是 Alloc 且大小能用接口符号表示）/ ret_ptr（base 是形参或全局）/ ret_int（界能投影到接口符号）； 每条 ret c 处的守卫（只含接口符号）→ ret_cond（同一个 c 取交集，至多 4 条）；形参可达的格在出口处与初值不同 → field / out_*； 经未知写失效过的 → invalidate。A-71 投影：含非接口符号的界换成它的数值界（来源标签保留），没有数值界则为 ±∞。

6.8 调度

  • A-80 solve：读全部 FIR；建函数表（D-07 处理重名）与全局大小表（D-34）；按直接调用 + 可静态解析的函数指针建全局调用图； Tarjan 求 SCC，逆拓扑序逐个求解；SCC 内（递归）按键排序各求一次，环内调用按未知处理并记账 recursion（01- §3.9）。
  • A-81 inline：同样的过程，范围限于本 TU。
  • A-82 求解过程单线程、确定性（所有遍历按键排序，不依赖指针地址）；并行求解 [P1]（按 SCC 层级分批）。

6.9 出告警

  • A-90：solve 给每条未被过滤的判定定一个汇合点 TU（汇合点函数的 FIR 所在 TU），写进 decisions/<tu>.json。
  • A-91：report / inline 阶段把 [文件, 行, 列] 经 FileManager + SourceManager::translateFileLineCol 换成 SourceLocation； 换不出来（文件不在本 TU）→ 退回汇合点函数的声明位置，并把原位置写进消息。按 F-33 组 note，按 F-35 排序后发出；同一进程内按指纹去重。

6.10 全函数性与上限

A-95 任何函数都必须产出合法摘要：不支持的构造降为未知、迭代超限置 ±∞、超时 / CFG 过大产出空摘要并标 skipped。 A-96 不得因单个函数 / TU 失败而中断整体：export 失败的 TU 记入 logs/，其中的函数在调用方看来是 not_exported；引擎对异常输入（读进来的 FIR 不一致、超出上限）一律返回错误码、 把该函数降级为 skipped，不靠 assert（release 构建里 assert 不生效，而 LLVM 不开异常）。
